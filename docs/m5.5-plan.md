# M5.5 내장 git 서버 — 구현 계획

- 기준: [design.md](design.md) v0.15 D21, §1.2 원격 인증, §1.5(내장 git 서버·pre-receive 규칙), §2.1 메타 브랜치 보호, §11.4 우회 차단, §11.5 서버 운영, §14 M5.5
- 완료 기준: **M5의 에픽 흐름이 내장 git 서버로 main까지 가고, 규칙 위반 push가 거부된다**
  - 규칙 위반 push: 메타 이벤트 수정, 남의 이름 이벤트, main 직접 push
  - 반영된 main은 외부 미러(GitHub `test-flightdeck`)에도 올라간다.

## 범위

| 포함 | 제외 (이후) |
|---|---|
| git smart HTTP(`git http-backend`를 서버가 CGI로 실행), `/git/<product>.git` | 코드 브라우징 웹 화면 (§1.5: 제공하지 않음) |
| 인증: git 전용 토큰 + 확장이 설정하는 credential helper | 조종수(M8)의 에픽 브랜치 쓰기 — 지금은 담당자만 |
| `pre-receive` ref 규칙(§1.5) | 체크포인트·세션 원본 retention 정리 |
| 기존 레포 가져오기, 빈 레포 만들기 | Google 로그인 실제 확인 (OAuth 클라이언트 없음) |
| 외부 미러(main·태그), 미러 실패 재시도 | 외부 git 방식 변경 없음 (그대로 지원) |
| 백업(`git bundle`)·복원 확인 | |
| 확장: 서버 레포 받기(clone), 원격 확인, 토큰 갱신 | |

## 미리 보이는 설계 문제 (구현 전 제안)

구현은 아래 제안대로 진행한다. design.md는 확인을 받은 뒤 고친다.

| # | 절 | 현재 서술 | 문제 | 제안 |
|---|---|---|---|---|
| Z1 | §1.5, §5 `repo` | 내장 방식이 기본이라고만 되어 있다 | 제품이 어느 방식인지 정하는 설정이 없다 | pipeline.yaml `repo: builtin`이면 내장, URL이면 외부. 내장 레포 주소 = `<서버>/git/<product>.git`. 미러는 `mirror: {url, refs: [main, "tags/*"]}`(내장일 때만). 방식 전환은 진행 중인 에픽이 없을 때만 한다. 기존 레포는 서버 명령 `--import-repo <url>`로 모든 ref를 한 번 가져오고, 없으면 빈 main 커밋으로 만든다 |
| Z2 | §1.5, §11.3 | 서버(반영 모듈)가 main에 push | 서버가 내장 레포에 직접 쓰면 서명·반영 코드가 외부 방식과 갈린다 | 서버의 작업 사본(`repos/<product>.git`)은 그대로 두고 **원격만 내장 레포(로컬 경로)**로 한다. 서명·반영 코드는 두 방식에서 같다. 서버의 push도 같은 pre-receive를 거치고, 서버 프로세스만 아는 push ID로 "서버"로 판정된다 |
| Z3 | §1.2 원격 인증 | 확장이 credential helper를 제공하고, 서버 로그인 세션으로 인증 | 로그인 세션 토큰은 승인 서명까지 할 수 있다. git이 읽을 수 있는 곳(파일)에 두면 에이전트도 읽을 수 있다 | **git 전용 토큰**(`POST /git/token`, 7일, git 경로에만 유효, 서버 키로 만든 HMAC이라 DB 없음)을 쓴다. 확장이 `<git 공용 폴더>/flightdeck/git-credentials`(0600)에 쓰고, 레포 설정에 그 파일을 읽는 credential helper를 넣는다. 하루 남으면 갱신. 비활성 멤버는 토큰이 있어도 거부. 에이전트 훅은 이 파일 읽기를 막는다(셸 우회까지는 못 막으나, 새어도 그 멤버가 할 수 있는 push뿐이다) |
| Z4 | §1.5 pre-receive 표 | ref별 허용 주체 | 판정에 필요한 세부가 없다(누가 만들 수 있나, fast-forward인가, 이벤트 내용 검사) | 아래 "pre-receive 규칙" 표. 훅은 서버 HTTP로 판정을 요청하는 작은 스크립트이고, 판정은 서버 안의 같은 코드(reducer)가 한다. 판정 중 오류는 거부(fail-closed) |
| Z5 | §1.5 미러 | 서버가 main(과 태그)만 미러 push | 미러 실패·미러 쪽 변경 처리 | 반영 직후 미러 push, 실패하면 1분 스캔에서 다시. 미러 main이 내장 main의 조상이 아니면(미러 쪽에서 누가 push) 덮지 않고 서버 로그·어드민 화면에 경고. 메타·에픽 브랜치는 미러하지 않는다 |
| Z6 | §1.5, §11.5 백업 | 백업은 서버 운영에 포함 | 방법이 없다 | `flightdeck-server backup <폴더>` = 내장 레포마다 `git bundle create --all` + `bundle verify`. 복원 = bundle에서 bare clone 후 서버 시작(훅은 시작할 때 다시 설치). DB는 `pg_dump`(운영 문서) |
| Z7 | §9.1 진입 | 담당자가 레포를 이미 갖고 있다는 전제 | 내장 방식에서 새 멤버가 레포를 받는 길이 없다 | 명령 `Flightdeck: 서버 레포 받기`(폴더 고르기 → clone → 열기). 레포를 열 때 원격 주소가 서버 레포가 아니면 알리고 "서버 레포로 바꾸기"를 준다 |

### 구현·시나리오 중 찾은 것

| # | 절 | 문제 | 제안 |
|---|---|---|---|
| Z8 | §1.5, Z1 | 설정을 `repo: builtin`으로 바꾼 직후 1분 스캔이 내장 레포를 **빈 레포로 먼저 만들어**, 서버를 다시 시작할 때 가져오기(`--import-repo`)가 건너뛰어졌다 | 내장 레포는 **서버 시작 때만** 만든다(가져오기 또는 빈 첫 커밋). 그 전의 요청은 "내장 레포가 아직 없다"로 거부한다. 어드민 화면에서 가져오기를 하는 기능은 이후 (구현함) |
| Z9 | §2.5 설정 버전, §11.3 2 | M5 에픽은 메모리 저장소 서버의 `sample-v1`에 고정됐는데, PostgreSQL 서버의 `sample-v1`은 M2 때의 다른 설정이었다. reducer가 그 설정으로 승인을 무효로 계산해, 서명된 반영 커밋 `736ae1a`를 main 감사가 "서버를 거치지 않은 커밋"으로 잡았다. 설정 버전 ID는 서버 DB 안에서만 유일하다 | `epic.started`에 **설정 내용 해시**(`config_hash`)도 적는다. reducer·서버는 받은 설정의 해시가 다르면 그 에픽을 "설정 불일치"로 표시하고 판정하지 않는다(조용히 다른 설정으로 계산하지 않는다). 버전 ID를 `<product>-<해시 앞 8자>`로 만드는 방법도 있다. 운영에서는 DB를 바꾸지 않으면 생기지 않지만, 서버 이전·복구 때 생길 수 있다 (사용자 결정: A안 = 해시 서명. 구현하고 design.md v0.16에 반영) |

### pre-receive 규칙 (Z4)

| ref | 멤버 | 서버 |
|---|---|---|
| `main`(반영 대상), `refs/tags/*` | 거부 | 허용 |
| `flightdeck-meta` | fast-forward만. 새 커밋은 병합이 아니고, `epics/<epic>/events/<ULID>-<member>.json` **추가만**(수정·삭제·다른 경로 거부). 파일이 이벤트 형식이고 이름이 내용과 맞으며, `author`와 파일의 멤버가 push한 멤버. 서버 서명 이벤트 종류는 거부 | 만들기 포함 fast-forward만, 추가만 (이벤트 내용은 서버가 만든 것) |
| `flightdeck/<epic>` | 담당자만(확장은 `epic.started` 서명을 받은 뒤 브랜치를 올린다). fast-forward만. 삭제 거부 | 허용 (main 병합 커밋, 반영 후 삭제) |
| `refs/flightdeck/ckpt/<epic>/<member>` | 그 멤버만 | 허용 |
| `refs/flightdeck/runs/<epic>` | 그 에픽의 담당자, fast-forward만 | 허용 |
| 그 밖 | 거부 | 거부 |

- 담당자는 서버 서명이 맞는 `epic.started.owner`다(reducer로 계산).
- 읽기(fetch·clone)는 활성 멤버 모두.
