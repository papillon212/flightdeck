# M8 조종수 모델 — 구현 계획

- 기준: [design.md](design.md) v0.17 §8.2(조종수 모델), §8.3(실시간 관찰), §8.4(의견), §8.5(조종 넘기기), §1.5(조종수의 에픽 브랜치 쓰기, M5.5 Z4), §2.4 `@live`, §14 M8
- 완료 기준: **관찰자가 1초 안에 조종수 작업을 보고, 의견이 에이전트까지 전달됨**
  - 조종수의 에이전트·에디터 편집이 관찰자의 읽기 전용 창에 1초 안에 적용된다. 대화(세션 기록)도 관찰자 화면에 블록 단위로 보인다.
  - 관찰자 의견 → 조종수 의견 패널 → "에이전트에 전달"(다음 도구 호출 뒤) / "급한 의견"(다음 도구 호출 거부)로 실제 에이전트(claude)에 닿는다.
  - 조종 요청·수락으로 조종수가 바뀌고, 새 조종수가 이전 조종수의 마지막 체크포인트·편집 기록에서 이어간다. 끊긴 조종수는 정해진 시간 뒤 담당자가 강제 인수한다.

## 범위

| 포함 | 제외 |
|---|---|
| 서버 ④: 에픽별 실시간 채널(편집·대화·의견·조종 요청), 접속 상태 | 여러 서버 인스턴스 사이 중계 |
| 조종수 확장: 편집 기록·대화 블록 스트림 보내기 | 관찰 뷰의 "조종수 커서 따라가기" (이후) |
| 관찰자: `@live` 읽기 전용 창(체크포인트 + 편집 기록으로 따라잡기 → 실시간 적용), 대화 뷰, 의견 보내기 | Codex 등 다른 에이전트 (M9) |
| 조종수: 의견 패널, 에이전트 전달(PostToolUse·UserPromptSubmit), 급한 의견(PreToolUse 거부, 1초 판정), 쓰레드로 남기기, 답장, 닫기 | |

## 미리 보이는 설계 문제 (구현 전 제안)

| # | 절 | 현재 서술 | 문제 | 제안 |
|---|---|---|---|---|
| L1 | §8.3, §11.5 통신 | WebSocket | Node에는 WebSocket 서버가 기본으로 없다(의존성 추가). 관찰자 → 서버 쪽은 드물다(의견·요청) | 서버 → 확장은 **SSE**(`GET /live/<epic>`, `text/event-stream`), 확장 → 서버는 **POST**(`/live/<epic>/send`). 의존성 없이 1초 안 지연을 낼 수 있고, 끊기면 마지막 받은 번호부터 다시 받는다(`Last-Event-ID`, 서버는 에픽별 최근 1,000건을 메모리에 둔다). 실시간 데이터는 저장하지 않는다(§11.5) |
| L2 | §8.2, §3.1 `pilot.changed` | 조종 상태는 서버 ④가 관리하고, 넘길 때마다 메타 이벤트 | 서버 메모리의 상태와 메타 이벤트 중 어느 것이 권한의 기준인지 | **기준은 메타 이벤트**(reducer). `pilot.changed {from, to, reason, ckpt, handoff_run?}`는 일반 이벤트이고 권한: `handoff`·`request`(수락)는 현재 조종수가, `takeover`는 담당자가 쓴다. 서버 ④는 접속 상태와 요청 전달만 한다. pre-receive·서명 요청도 reducer의 조종수를 쓴다 |
| L3 | §8.2 | 조종수는 작업 폴더 쓰기·에이전트 실행 | 단계 통과(구현 완료·리뷰 요청·테스트 보고·수정 제안 반영)를 누가 하나. 지금은 담당자만 | **작업 결과를 내는 요청은 현재 조종수**가 한다(테스트 보고·구현 완료·리뷰 요청·수정 제안 반영·에픽 브랜치 쓰기). 처음 조종수는 담당자라 지금과 같다. 승인 규칙의 "담당자"(자기 승인, §4.2)와 쓰레드 권한은 그대로 담당자 |
| L4 | §8.5 3·4 | 체크포인트 생성 → push → 새 조종수의 창이 쓰기 가능 | 새 조종수의 작업 폴더가 이전 조종수의 미공유 작업을 이어받아야 한다. 편집 기록 seq도 이어져야 한다 | 넘기기 = 이전 조종수가 저장·외부 변경 기록 → 체크포인트 → push → 편집 기록 업로드(M7) → `pilot.changed {ckpt}`. 새 조종수의 확장은 그 체크포인트로 작업 폴더를 만들고(에픽 브랜치 끝 위에 체크포인트 트리 복원), 서버의 편집 기록·메모를 받아 로컬 편집 기록으로 둔다. 체크포인트의 `Flightdeck-Seq`와 서버 마지막 seq가 다르면 넘겨받지 않고 알린다 |
| L5 | §8.5 이탈 | 10분 끊기면 강제 인수 | 끊김 판단 | 서버 ④의 접속 상태(SSE 연결)로 판단. 조종수 연결이 끊긴 지 `pilot.takeover_after_minutes`가 지나면 담당자 확장에 "강제 인수" 명령을 연다. 인수 기준은 서버에 올라온 마지막 편집 기록과 그 조종수의 마지막 체크포인트(L4와 같은 절차, `reason: takeover`). 그 뒤 올라오는 이전 조종수의 편집 기록 업로드는 서버가 거부한다(E4: 올리는 사람 = 현재 조종수) |
| L6 | §8.3 대화 스트림 | 세션 기록 파일 따라 읽기 + 훅 이벤트 | 훅은 짧게 끝나는 프로세스다 | 훅은 세션 기록 파일 경로를 로컬 상태에 적어 두고, **조종수 확장이 그 파일을 따라 읽어** 허용 목록 필터(§6.4) 뒤 블록을 보낸다. 훅 이벤트(도구 시작·끝)도 확장이 훅 기록(trace)에서 읽어 "작업 중" 표시로 보낸다 |
| L7 | §8.4 의견 | 의견 패널, 전달 대기열 | 훅과 확장 사이 전달 경로 | 조종수가 "에이전트에 전달"을 고르면 확장이 `<git 공용 폴더>/flightdeck/opinions/<epic>.jsonl`에 넣는다. 훅이 다음 PostToolUse(실행 중)·UserPromptSubmit(멈춤)에서 꺼내 추가 컨텍스트로 붙이고 "전달됨"을 남긴다. 급한 의견은 PreToolUse가 거부 사유로 돌려준다(같은 메시지 판정: 직전 거부 1초 안). 전달된 의견은 세션 원본에 남는다 |
| L8 | §2.4 `@live` | 관찰자용 읽기 전용 창 | 질문·리뷰용 읽기 전용 창(같은 경로)과 관계 | 관찰은 별도 폴더 `<epic>@live`. 조종수의 마지막 체크포인트 + 그 뒤 편집 기록으로 시작하고, 실시간 편집을 순서대로 적용한다. seq가 빠지면 서버 편집 기록(M7)에서 채운다. 파일은 읽기 전용으로 연다 |
