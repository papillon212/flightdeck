### U8: git 서버 제공 (사용자 제안, 2026-10-04, 반영됨)

지금 설계는 git 호스트를 push·fetch 대상으로만 쓴다(D12). 그래서 호스트를 바꾸는 데 확장 쪽 변경은 거의 없다. 바뀌는 것은 **보호 규칙을 누가 지키게 하느냐**다.

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| (a) 내장 git 서버 | flightdeck-server가 git smart HTTP(`git http-backend`)를 직접 제공한다. 인증은 Google 로그인 세션(확장이 git credential helper 제공). 서버의 `pre-receive` 훅이 ref 규칙을 강제한다 | 호스트 비용 없음. 보호 규칙을 **GitHub보다 세밀하게** 강제할 수 있다: main은 서버만, `flightdeck-meta`는 **이벤트 파일 추가만**(수정·삭제·이력 재작성 거부, 일반 이벤트의 `author`가 push한 멤버와 같은지까지 확인), 체크포인트 ref는 본인 것만. U4·일반 이벤트 위조 문제가 서버에서 막힌다 | 서버가 git 원본이 된다: 백업·디스크·가용성을 직접 책임진다. 서버가 죽으면 push·fetch가 멈춘다(조종수의 로컬 작업은 계속). 코드 브라우징 웹 화면이 없다 |
| (b) 외부 git 연동 | 지금 설계. GitHub·GitLab·Gitea 등 | CI/CD 등 기존 도구와 바로 연계 | 비공개 레포의 브랜치 보호는 요금제에 따라 다르다(M2-2에서 확인). 메타 브랜치 "추가만" 같은 규칙은 호스트가 강제하지 못해 확장·서버의 감지에 의존 |
| (c) 내장 + 외부 미러 | (a)를 원본으로 하고, 서버가 main(과 태그)만 외부 git에 미러 push한다 | CI/CD는 main만 보면 되므로 연계를 유지하면서 외부 호스트는 최소 구성 | 미러 지연(수 초). 외부에서 main에 직접 push하면 안 된다(미러 대상은 읽기 전용으로) |

- **제안**: (a)·(c)를 기본으로 하고 (b)도 지원한다. 이를 위해 `GitHost` 설정에 "보호 규칙을 서버가 강제하는가(내장) / 호스트 설정에 의존하는가(외부)"를 두고, 외부일 때만 확장의 이력 재작성 감지와 관리자 경고를 켠다.
- **시기**: M2는 지금대로 외부(GitHub `test-flightdeck`)로 진행한다. GitEngine은 호스트와 무관해서 M2 결과가 그대로 쓰인다. 내장 git 서버는 main push 규칙과 엮이므로 **M5(반영 서버) 직후 별도 마일스톤**으로 넣는 것을 제안한다.
- 승인되면 design.md에 D21(git 호스트 방식)과 §1·§2.1·§11.4·§14를 반영한다.

### M2-2 GitHub 확인 (2026-10-04, `spikes/12-meta-github/check.ts`)

`papillon212/test-flightdeck`, 클론 2개(A, B). 확인 후 시험 브랜치는 지웠다.

| 항목 | 1차 | 개선 후 |
|---|---|---|
| A 이벤트 추가 + push | 5.8초 | **3.1초** |
| B sync로 받기 | 5.8초 | **2.9초** |
| A·B 동시 각 5건 → 양쪽 같음, 병합 커밋 | 34초, 같음, 0 | 21~25초, 같음, 0 |
| 에픽 브랜치 push / B 읽기 전용 창 | 3.0초 / 5.6초 | 3.0초 / **2.9초** |

- 원격 왕복(SSH 연결) 한 번이 약 3초다. 개선은 왕복 수를 줄인 것이다.
  - fetch 전에 `ls-remote`로 브랜치 존재를 확인하지 않는다(없다는 오류로 판단).
  - 보낼 것만 있으면 fetch 없이 바로 push하는 빠른 길을 두었다.
- 빠른 길의 함정을 테스트로 잡았다. 원격이 **내 끝의 조상으로 되돌려진** 경우 내 push가 fast-forward로 받아들여져 재작성을 감지하지 못한다. push에 lease(원격이 마지막으로 본 끝 그대로일 때만)를 걸어 해결했다.
- 브랜치 보호 가능 여부: `gh`가 다른 계정(dhlee-apm)으로 로그인돼 있어 API로 확인하지 못했다. 레포 Settings → Branches에서 확인이 필요하다. 내장 git 서버(D21)가 기본이 되면 이 의존은 사라진다.
