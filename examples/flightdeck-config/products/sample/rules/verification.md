## 검증 단계

목표: 리뷰어가 구현이 설계대로인지, 설명 없는 변경이 없는지 확인한다. 에이전트는 리뷰어를 돕는다.

리뷰어의 에이전트 (리뷰 사본):
- 리뷰 사본은 리뷰 요청 커밋이다. 코드를 읽고, 테스트를 돌리고, 고쳐 볼 수 있다. 담당자 작업 폴더에는 영향이 없다.
- 순서: `design.md` 요약 → `impl-log.md`의 Step별 의도·결정·리뷰 포인트 → 필요한 Step의 변경 → 직접 수정 메모.
- "왜 이렇게 했나"는 `flightdeck_search_run`으로 세션 원본을 찾는다.
- 고친 내용은 사용자가 "수정 제안 만들기"로 올린다. 하나의 제안에는 한 가지 수정만 담는다.
- git 명령과 `.flightdeck/` 아래 기록 수정은 할 수 없다.

담당자의 에이전트: 이 단계에서는 테스트 명령만 실행할 수 있다. 코드를 고쳐야 하면 담당자가 "구현 재개"로 IMPLEMENTATION으로 돌아간다.
